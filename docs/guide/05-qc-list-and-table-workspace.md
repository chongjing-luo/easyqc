# EasyQC 质控名单与表格工作区

## 1. 两张逻辑表：草稿与总名单

“质控名单导入”与“质控前名单”看起来都使用表格，但数据权威不同：

| 页面 | 数据来源 | 是否权威 | 新增列写到哪里 |
|---|---|---|---|
| 质控名单导入 | 本次文件、目录、文本形成的完整导入草稿 | 否 | 当前完整草稿 |
| 质控前名单 | `Table/easyqc_all.csv` | 是 | 当前项目总名单 |
| 质控结果 | 总名单与评分 JSON 的重建投影 | 派生 | 只持久化普通总名单列 |

导入后筛选、排序或分页不会把草稿偷换成总名单。只有用户选择写入模式并确认，草稿才进入 `easyqc_all.csv`。

## 2. 导入来源

### 2.1 直接子文件夹

选择一个根目录后，默认模式把其下一层普通目录作为记录来源。该模式适合“一个一级文件夹对应一个条目”的常见结构。

### 2.2 模式匹配文件或目录

高级目录导入由三个正交选项组成：

| 维度 | 可选值 |
|---|---|
| 目标类型 | 文件夹、文件、两者 |
| 匹配方式 | 开头、结尾、包含、通配符、正则表达式 |
| 搜索范围 | 直接下级、精确深度、全部层级 |

结果最多形成两列：

- 匹配目标本身的 basename；
- 从所选根目录到目标之前的相对父路径。

目标就在根目录下一层时，相对父路径可以为空。搜索会跳过符号链接，避免循环遍历或把目录外对象误纳入项目。

示例：在 `/study/derivatives` 下匹配精确深度 3、后缀为 `_T1w.nii.gz` 的文件，可以保留 `sub-001/ses-01/anat` 作为相对父路径，同时把文件名放入另一列。之后再用 Formula 构造完整路径或提取 ID。

### 2.3 表格文件

支持 CSV、Excel、TXT 和 LIST。TXT/LIST 适合一行一个值或可由当前读取规则解释的分隔文本。Excel 依赖 pandas 可用的 Excel engine；缺少引擎时应安装相应可选包后重试。

### 2.4 直接输入

可粘贴逗号或空白分隔的多行内容。它适合快速建立小名单，也可先导入一列，再通过新增列形成 `easyqcid` 和其他字段。

## 3. 导入草稿操作

草稿是完整、独立的 DataFrame。表格上的筛选只影响当前显示，不会改变 Formula 的输入范围；新增列总是基于完整草稿计算。

草稿支持：

- 用工具栏“增加空行”增加一行空白记录；
- 用“删除行”按钮，通过结构化条件删除匹配行；
- 选中单元格后右键复制，或使用 Ctrl+C（macOS 为 Cmd+C）。导入草稿不提供质控跳转。

删除不是“选中几行立即删除”。用户先在与筛选器一致的条件编辑器中描述目标，预览匹配范围，再执行变更。这种逻辑在大表中比依赖鼠标多选更可审计。

## 4. `easyqcid` 准入合同

### 列重命名

“质控名单导入”和“质控前名单”的工具栏均提供“重命名列”。点开后选择原列并输入新名称，无需预选单元格。导入预览允许把 `rest` 等列直接改为 `easyqcid`；这只修改当前导入草稿，写入前仍需通过下面的编号校验。总名单中的 `easyqcid` 和系统评分结果列不可改名。

列改名保留数据值、类型、顺序和当前表格的筛选/排序/列显示状态，例如文本 `01`、`02` 不转为数字。名称与已有列或项目常量冲突时拒绝。模块命令和模块筛选不自动改写，需要用户自行维护旧列引用；历史评分 JSON 不变。

### 编号校验

导入源可以暂时没有 `easyqcid`，因为用户可能需要先从文件名提取它，或新增一个固定值列。但写入质控总名单前必须满足：

- 存在 `easyqcid` 列；
- 每个值非空；
- 精确值唯一；
- 大小写折叠后仍唯一；
- 每个值满足允许的标识符规则；
- 列名不与项目常量重叠。

例如 `Sub01` 与 `sub01` 会被拒绝，因为它们在大小写不敏感的文件系统或人工沟通中容易形成身份碰撞。

## 5. 写入总名单的三种模式

### 5.1 替换整个名单

候选草稿成为新的 `easyqc_all.csv`。它不会删除 `RatingFiles/` 中已有评分；被移出总名单的身份只是不再出现在当前左连接结果中。

### 5.2 追加行

追加只要求草稿和总名单都包含合法 `easyqcid`，不要求其他列相同，也不要求两边的编号集合相同。同名列对齐，新列保留，缺少的字段补空；原列在前，新出现的列按导入顺序放在末尾。

- **去重**：保留已有行，只追加新身份；重复编号整行跳过，不用其中的新字段补写原行。
- **替换匹配行**：只更新同一编号在导入表中实际提供的列，未提供的列保留旧值；导入表已经提供的列中的空值也会覆盖旧值。随后追加新身份。

例如旧名单有 `easyqcid、site、path`，导入表有 `easyqcid、run`，合并后为 `easyqcid、site、path、run`。选择替换时，重复编号的 `site/path` 保持原值，`run` 使用导入值；新编号的 `site/path` 留空。

已有行顺序不变，新编号按导入顺序追加。单张导入表内仍不允许重复或空白编号、重复列名、与常量冲突的列；两张表列不同本身不再构成错误。名单变更不会删除或改写评分JSON。

### 5.3 按 `easyqcid` 合并列

该模式以 `easyqcid` 一对一对齐并扩展字段。已有列发生冲突时可选择：

- **保留现有值**；
- **使用导入值更新**。

预览会先显示影响范围。重复身份、列冲突策略缺失或常量重名都在发布前失败。

## 6. 统一表格工具

质控名单导入、质控前名单和质控结果共享同一种交互模型：

- 筛选；
- 排序；
- 新增列；
- 列显示；
- 删除行/删除列（只在允许修改权威数据的页面）；
- 分页和每页数量；
- 横纵滚动与固定身份列。

### 6.1 类型感知筛选

通用操作符包括：

| 数据类型 | 操作符 |
|---|---|
| 全部类型 | `==`、`!=`、`isna`、`notna`、`in`、`not_in` |
| 文本 | `contains`、`startswith`、`endswith` |
| 数值/日期时间 | `<`、`<=`、`>`、`>=`、`between` |
| 布尔 | 相等、不等、空值检查 |

条件可以组成 AND/OR 分组。用户操作可视化条件，不编辑 JSON；JSON operation 只是 Core 内部的确定性表示。

### 6.2 多列排序

排序规则按优先级应用。例如先按 `site` 升序、再按 `age` 降序。排序只改变位置投影，不改 CSV 行值；关闭或清空排序即可回到源顺序。

### 6.3 列显示与顺序

“列显示”控制当前可见列和显示顺序。`easyqcid` 始终是第一列、可见且固定，不能隐藏或移动到其他位置。结果导出按当前显示列、筛选和排序生成投影，因此导出前应检查列状态。

## 7. 删除行与删除列

质控名单导入和质控前名单都采用与筛选/列显示一致的批量逻辑：

- 删除行：用条件编辑器定义行集合；
- 删除列：用复选清单选择一个或多个字段；
- `easyqcid` 永远不能从总名单删除；
- 变更目标是草稿或 `easyqc_all.csv`，不是评分目录。

删除总名单行或列不会触碰评分 JSON。这个边界允许用户整理当前工作范围，同时保留已经产生的人工判断。若要永久删除评分，应在经过独立备份和审计后使用专门的数据治理流程，而不是名单按钮。

## 8. 新增列

“新增列”把 Formula 计算结果物化为普通值列：

- 可以引用一个或多个现有列；
- 可以完全不引用源列而产生固定值；
- 不能覆盖已有目标列；
- 预览错误未解决时不能提交；
- 只保存最终值，不保存公式或 AST。

导入页的新增列作用于完整导入草稿；质控前名单与结果页的新增列作用于总名单。结果页不会把评分派生列当作 Formula 输入，以免把可重建结果误写成新的主数据依赖。完整语法见[新增列与 EasyQC Formula](06-derived-columns-and-easyqc-formula.md)。

## 9. 分页与大表显示

Core 对完整数据执行筛选和排序，但结果状态只保存源位置数组。Qt model 每次只请求当前页窗口，不为整个表建立成百上千个 QWidget。

- 共享名单工作区默认每页 200 行；
- 导入预览默认每页 100 行；
- 结果页默认每页 25 行；
- QC 队列默认约显示 8 行。

固定 `easyqcid` 区和普通列区共享选择、行高与纵向滚动。外部纵向滚动条贯穿两块表格；普通列拥有自己的横向滚动。这样纵向滚到底部时，固定列与其他列仍指向同一行。

## 10. 表格右键菜单

质控前名单、质控结果和正在质控的队列表格支持单元格多选。单格右键有五个一级入口：

1. **复制**：复制选中格子的文本；
2. **打开质控页**：选择模块，仅打开质控页，不自动执行查看器；
3. **已有质控记录**：按保存的模块快照打开精确的 `(easyqcid, module, rater)` 记录，默认只读；
4. **仅执行命令**：执行所选模块的当前行命令，打开独立命令输出窗，不切换现有评分页，不保存评分；
5. **打开质控页并执行命令**：进入模块，并显式启动当前条目的查看器。

配置“结果关联”后，相关来源会加入上述模块/记录子菜单；来源项注明自己的条目、模块和评分者，不使用目标行的数据执行来源命令。来源模块跳转也默认只读，可手动取消只读后编辑原始来源评分。

多格选区右键只显示“复制”，不会触发质控或命令动作。在选区内右键保持选区；在选区外右键重选该格。可拖选或用 Ctrl/Shift 扩展选择；选择单元格不会切换当前评分对象，也不会丢弃未保存草稿。

复制按当前可见的行列顺序输出 TSV；固定列只输出一次，不复制隐藏列；不连续选择的空位留空。制表符、换行、引号按 TSV 转义。复制范围是当前已选单元格；批量导出全部筛选结果仍用“导出”。关闭独立命令输出窗口只隐藏输出，不等于结束已启动进程；启动/终止仍按原有模块进程控制设置执行。

菜单不是简单列出全部文件。Core 先验证当前 `easyqcid`、模块队列和评分身份，避免从错行启动或把另一质控员的记录当成当前记录。

## 11. 导出结果表

结果页导出当前已经应用的：

```text
筛选 + 多列排序 + 可见列及顺序
```

导出按块读取当前投影并写入同目录临时文件，完成后原子替换目标。若用户取消或过程失败，已有目标文件保持不变。导出 CSV 是结果快照，不取代评分 JSON 权威。

## 12. 常见失败及恢复

| 失败 | 原因 | 处理 |
|---|---|---|
| 无法写入名单 | 缺少/空白/重复 `easyqcid` | 在草稿中新增或修正身份列 |
| case-only 冲突 | 两个身份只在大小写上不同 | 为其中一个分配真正不同的稳定 ID |
| 追加被拒绝 | 导入表内部有重复编号/列名，或列与常量/关联输出冲突 | 根据错误提示修正冲突；不必统一两张表的全部列 |
| 常量与列冲突 | 命令上下文会出现两个同名来源 | 重命名候选列或项目常量 |
| Excel 导入失败 | 缺少兼容 engine 或文件损坏 | 安装对应 engine，确认文件类型后重试 |
| 模块筛选失效 | 引用的总名单列已删除 | 编辑模块筛选或恢复该列 |
