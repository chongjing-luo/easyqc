# 07 附录:数据文件说明

日常使用不需要这一章。三种时候回来查:**备份迁移、多人协作、想读懂磁盘上的数据**。

## 1. 项目文件夹里都有什么

```text
easyqc_项目名/
├── settings_项目名.json    项目设置:常量、模块清单(文本编辑器可看,不建议手改)
├── Table/
│   └── easyqc_all.csv      质控总名单(唯一数据底稿;同名 .types.json 是列类型缓存,可删)
├── modules/                每个模块一个小 JSON(导出/导入的就是这种格式)
└── RatingFiles/            评分档案,按 模块/评分者 分层
    └── AnatQC/lcj/AnatQC-lcj-sub001.json     一条评分一个文件
```

**备份 = 拷贝这个文件夹;迁移 = 拷过去后"导入项目"。** 图像数据不在其中——路径才在(名单列 + 常量),换机器要按新路径改常量。

软件安装目录(不在项目里)还有:`projects.json` 项目登记表、`modules/` 模板库、`constant_templates.json` 常量模板、`logs/` 日志(应用日志留 30 天,查看器命令日志留 14 天)。

## 2. 一条评分文件长什么样

```json
{
    "name": "AnatQC",              ← 模块名
    "rater": "lcj",                ← 评分者
    "easyqcid": "sub001",          ← 条目
    "scores": {
        "1": { "label": "skullstrip", "num": "0-4", "num_": "0,1,2,3,4", "value": "3" },
        "2": { "label": "fs_recon",   "num": "0-4", "num_": "0,1,2,3,4", "value": "2" }
    },
    "tags":  { "1": { "label": "checkdone", "value": true } },
    "notes": "颞叶皮层缺失,冠状位 45-60",
    "time":  "2026-10-05 14:32:10",
    "code":     "freeview …模板原文…",        ← 当时的命令模板
    "code_exe": { "0": "freeview -v /data/…/sub001/orig/001.mgz …" },  ← 当时实际执行的完整命令
    "schema_version": 3
}
```

要点:文件名 = `模块-评分者-条目`;内容是**评分 + 当时模块配置的完整快照**(所以旧记录能在模块改版后原样重开);文件里没有名单、没有图像。改判 = 重新保存 = 覆盖这个文件,**没有历史版本**,要留底自己拷贝。

## 3. 并发与数据安全(一句话版)

- 所有保存都是"先写临时文件再原子替换",断电/崩溃最坏丢最后一次保存,不会产生写坏一半的文件。
- 同一项目被两个窗口同时使用时,写锁和版本检查会拦下冲突的那一次操作并报错——重试即可,不会静默覆盖。

## 4. 命令行速查

```bash
./start.sh                                   # 正常启动
./start.sh 项目 模块 评分者 条目号              # 直达某条的评分窗口(会开界面)
python easyqc.py --version                    # 版本
```

## 5. 边界与容量

- 纯本地软件:数据不出这台电脑,无联网、无数据库。
- 常规规模:约 10 万行、300 列没问题,内存建议 16 GiB;更大的表先分项目。
- 平台:Windows / macOS / Ubuntu 都可运行;界面与命令细节以 Linux 验证最充分,跨平台首次使用先拿几条数据试。
- 不做的事:不算图像质量指标、不做自动/AI 评分、不替你统一评分标准——上游指标(如 MRIQC 的)可以导进名单当筛选条件用。
