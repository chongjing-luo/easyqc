# EasyQC 外部查看器命令实时输出设计

## 1. 背景

EasyQC 通过 `core/code_executor.py` 异步启动 Freeview、FSLeyes、MRView 等
外部查看器。源码从 Terminal 启动时，用户过去可以在 Terminal 中观察命令输出；
冻结后二进制通常没有可见控制台，当前异步启动路径又把 `stdout` 发送到
`DEVNULL`，仅把 `stderr` 暂存到启动失败诊断文件。因此，正常输出、进度、警告
以及启动探测期之后发生的错误无法被用户查看。

本设计为质控窗口增加可折叠的实时命令输出面板，同时保存完整的本地会话日志。
它延续现有架构约束：所有外部查看器仍只能经由 Core 的 `CodeExecutor` 启动，
GUI 不直接创建或控制外部进程。

## 2. 已确认的产品决策

1. 同时实时显示并保存 `stdout`、`stderr`。
2. 输出面板位于质控页面底部，不打开独立窗口。
3. 面板记住上一次展开或收起状态；启动命令不强制改变状态。
4. 所有命令采用一个按时间排列的会话时间线，不使用标签页。
5. 每次启动 EasyQC 建立一个命令输出会话，日志保留 14 天。
6. GUI 只保留最近 5,000 行，磁盘日志不因 GUI 上限而截断。
7. 底层采用“子进程写入文件、Core 增量读取、GUI 定时刷新”，不使用可能堵塞
   的无人消费管道，也不把进程控制迁移到 Qt `QProcess`。

## 3. 目标与非目标

### 3.1 目标

- 冻结版与源码版都能在质控窗口内观察查看器命令输出。
- 大量输出不能阻塞 GUI 或使外部进程因为管道写满而挂起。
- 每条输出可以追溯到命令、模块、质控员和 `easyqcid`。
- 非零退出、启动失败、正常退出和仍在运行必须可区分。
- 完整会话日志在 EasyQC 重启后仍可用于调试。
- Linux、Windows 与 macOS 使用同一个 Core 合同和同一种 GUI 交互。
- 保持现有冻结版子进程环境隔离、`shell=False/True` 设置和进程组控制。

### 3.2 非目标

- 不提供命令输入框或交互式 Terminal。
- 不向外部查看器的标准输入发送内容。
- 不替代 FreeSurfer、FSL 或其他软件自身的日志系统。
- 不将命令输出写入项目文件夹、评分 JSON 或 Master QC list。
- 不把本功能设计成安全沙箱；命令仍以当前登录用户权限运行。
- 不保证外部程序在重定向输出后仍按行立即刷新。若程序自身缓存输出，内容只能在
  它主动刷新或退出后出现。

## 4. 方案选择

### 4.1 采用方案：Core 输出日志池 + GUI 定时增量读取

每条命令分别把 `stdout` 和 `stderr` 写入 Core 创建的二进制暂存文件。Core
按文件偏移量增量读取新增字节、进行安全文本解码、生成带身份和序号的输出事件，
并追加到当前会话日志。Qt 使用约 200 ms 的定时器读取 Core 事件并成批更新面板。

该方案具有以下性质：

- 子进程直接写文件，不存在 PIPE 无人消费导致的反压或死锁。
- GUI 收起时定时采集仍继续，磁盘日志不会停止。
- Shell 包装进程退出后，其派生进程若仍持有输出文件，输出仍可继续被采集。
- EasyQC 异常退出时，已写入的会话日志和原始暂存文件可保留诊断证据。
- 约 200 ms 的显示延迟换取了更简单、跨平台且可恢复的生命周期。

### 4.2 未采用方案

- `PIPE` + 后台线程：延迟略低，但需要处理线程关闭、无限队列、字符边界、派生
  进程继承管道和应用退出顺序，风险高于收益。
- Qt `QProcess`：信号机制方便，但会破坏“GUI → Core”依赖方向，并使 CLI 和
  非 Qt 测试无法复用唯一进程边界。

## 5. 架构与职责

```text
QtCommandOutputPanel ──poll(last_sequence)──▶ QcWorkflowService
        ▲                                      │
        │ output events                        ▼
        └──────────────────────────── CommandOutputJournal
                                                   ▲
                                                   │ register/finalize
                                                   │
                                            CodeExecutor
                                                   │
                               stdout/stderr files │
                                                   ▼
                                           External viewer
```

### 5.1 `CommandOutputJournal`（Core）

新增 toolkit-neutral 的 Core 组件，职责只有命令输出的注册、增量采集、会话日志、
有界内存历史和保留期清理。

主要合同：

- `register_execution(context, command, stdout_path, stderr_path)`：登记一条执行，
  分配稳定的会话内编号，例如 `C001`，写入 START 和 CMD 记录。
- `poll()`：按既有偏移读取新增输出，以有限批量生成事件并写入会话日志。
- `finalize(execution_id, returncode)`：完成最后一次采集并写入 EXIT 记录。
- `events_since(sequence)`：非破坏性返回指定序号之后的事件，使多个窗口不会互相
  “抢走”事件。
- `status()`：返回会话日志路径、文件日志可用性和退化原因。

该组件不启动、终止进程，不依赖 Qt，也不修改项目数据。

### 5.2 `CodeExecutor`（Core）

`CodeExecutor` 继续作为唯一外部进程控制器：

- 创建每条命令的 `stdout` / `stderr` 暂存文件并传给 `Popen`。
- 继续使用清理后的冻结版子进程环境。
- 启动后向 journal 登记命令和调用方提供的执行上下文。
- 启动探测期内非零退出时，先完成日志采集，再抛出 GUI 可见错误。
- 在轮询、显式关闭和应用关闭时完成进程状态与输出日志收尾。
- Windows 上只有在父进程文件句柄关闭、子进程结束且 journal 不再读取后才删除
  可删除的暂存文件。

### 5.3 `QcWorkflowService`（Core）

启动查看器时构造执行上下文并传给 `CodeExecutor`：

- 模块名；
- 质控员；
- 当前 `easyqcid`；
- `MULTICMD` 中的命令序号；
- 展开后的实际命令。

它同时向 GUI 暴露只读的命令输出查询接口。GUI 不访问 `Popen`、暂存文件或日志
内部路径。

### 5.4 `QtCommandOutputPanel`（GUI）

新增只读输出面板，仅负责：

- 定时请求 Core 中的新事件；
- 按事件类型渲染文本；
- 保持最多 5,000 个文本块；
- 管理复制、清空显示、打开日志和展开状态；
- 显示文件日志不可用等退化信息。

GUI 不启动进程，不直接读取子进程文件，也不决定进程何时终止。

## 6. 输出事件与时间线格式

Core 事件至少包含：

```text
sequence       会话内严格递增整数
timestamp      带时区的本地时间
execution_id   C001、C002……
kind           start | command | stdout | stderr | exit | warning
text           安全解码后的文本
module_name    模块名
rater          质控员
easyqcid       当前条目标识
returncode     仅 exit 事件使用
```

用户看到的示例：

```text
[10:24:31.184] [C001] START  module=AnatQC rater=rater1 easyqcid=SUB001
[10:24:31.185] [C001] CMD    freeview /data/SUB001/mri/orig.mgz
[10:24:31.307] [C001] OUT    reading volume ...
[10:24:31.410] [C001] ERR    warning: optional surface not found
[10:26:04.021] [C001] EXIT   code=0
```

`stderr` 不自动等于执行失败，因为许多科研软件把进度和普通警告写到 stderr；
只有非零退出码或启动异常标记为失败。不同 stream 分别采集，因此 stdout 与
stderr 之间的绝对先后只能反映 EasyQC 观察到的顺序，不能宣称为操作系统级全序。

## 7. 文本、安全与边界处理

- 输出按文本处理，使用 UTF-8 增量解码并以 replacement character 处理非法字节。
- 保留换行和制表符；移除或转义 ANSI 控制序列及其他不可打印控制字符，外部输出
  永远是数据，不解释成 HTML、富文本或命令。
- 超长单行按安全块增量显示和记录，不能令一次 GUI 更新无限增长。
- 每个定时周期设置读取字节预算；持续高输出时后续周期继续追赶，GUI 事件循环
  不被一次采集长期占用。
- 实际展开命令、路径、模块名、质控员和 `easyqcid` 会进入本地日志，可能包含研究
  数据标识。日志只写当前用户的日志目录，文档明确提醒分享日志前脱敏。
- 不记录整个环境变量映射，避免把 token 或其他环境秘密写入日志。

## 8. 日志存储与生命周期

### 8.1 位置和命名

使用现有 `utils.logger` / platformdirs 决定的当前用户日志根目录，在其中建立专用
子目录 `viewer-commands/`。每次应用启动建立一个逻辑会话日志：

```text
viewer_commands_YYYYMMDD_HHMMSS_<pid>.log
```

原始 stdout/stderr 暂存文件位于该会话的内部 spool 目录，不出现在项目目录。
若用户日志根目录不可写，spool 明确退化到操作系统临时目录，以便 GUI 仍能捕获
当前运行期间的输出；此时不宣称具有跨重启的完整会话日志，并在面板持续显示
持久化不可用状态。

### 8.2 保留期

- 启动时只清理 EasyQC 自己命名且最后修改时间超过 14 天的命令会话日志和 spool。
- 不清理一般 EasyQC 日志、项目文件或其他应用文件。
- GUI 的 5,000 行限制只影响显示，不能截断会话日志。
- 会话日志不主动丢弃输出。若磁盘已满、目录不可写或追加失败，命令继续运行，
  面板显示清晰的“文件日志不可用”警告并保留仍能显示的内存输出。

### 8.3 收尾与恢复

- 正常退出时执行最后一次采集、刷新并关闭会话日志。
- 已完成且已采集的暂存文件在关闭全部相关句柄后删除。
- 异常退出遗留的 spool 在下次启动时保留为诊断证据，直到超过 14 天再清理。

## 9. GUI 设计

### 9.1 位置与尺寸

面板固定在 Qt 质控控制器窗口底部，作为可调整高度的底部区域，不覆盖名单、评分、
标签或备注。用户可以拖动分隔线改变高度。展开状态和上一次有效高度使用
`QSettings` 保存；下次打开任意质控窗口时恢复。

执行命令不会强制展开或收起面板，完全尊重用户上次状态。收起时采集和写日志仍
继续。

### 9.2 控件

面板标题栏保持简洁：

- 展开/收起按钮；
- 标题“命令输出” / “Command output”；
- 当前运行命令数量；
- “复制全部”：复制当前显示的最多 5,000 行；
- “清空显示”：仅清除面板并把当前事件序号设为新起点，不删除磁盘日志；
- “打开日志”：使用系统默认方式打开当前完整会话日志；文件日志不可用时禁用并
  给出原因。

正文使用系统等宽字体和只读纯文本控件。stdout、stderr、命令、退出状态使用不同
但克制的文本颜色，同时保留 `OUT`、`ERR`、`CMD`、`EXIT` 前缀，不能只依赖颜色
传达含义。

### 9.3 滚动行为

- 用户位于底部时，新输出自动跟随。
- 用户向上查看历史时，新增输出不得抢走滚动位置。
- 回到底部后恢复自动跟随。
- 面板使用文本控件的 maximum block count 保持最近 5,000 行，避免重复复制整个
  文档造成界面卡顿。

### 9.4 双语和可访问性

所有固定控件、状态和警告支持中英文即时切换；用户命令与外部输出不翻译。
面板、按钮和输出区提供 accessible name，键盘可以聚焦、复制、展开和收起。

## 10. 错误处理

| 情况 | 行为 |
|---|---|
| 可执行文件不存在 | 写 START/CMD/ERROR，现有 GUI 错误路径显示失败 |
| 启动探测期非零退出 | 采集完整可用 stderr，写 EXIT，GUI 显示受限摘要 |
| 启动后稍晚非零退出 | 时间线写 EXIT code，错误状态可见，完整输出留在日志 |
| 日志目录不可写 | 查看器继续启动；面板显示持久化不可用警告 |
| 单个输出文件暂时无法读取 | 写一次去重 warning，后续轮询重试，不静默丢失 |
| 非 UTF-8 输出 | replacement 解码，记录发生过解码替换 |
| 多命令同时输出 | 每行保留 execution id；按观测序列进入统一时间线 |
| 面板收起 | 不停止采集，不改变日志完整性 |
| GUI 关闭 | 最后采集并关闭 journal；现有进程控制策略保持不变 |

## 11. 性能约束

- GUI 定时周期目标约 200 ms，不要求毫秒级 Terminal 仿真。
- 单周期读取与渲染都有固定预算；输出积压通过多周期追赶。
- 内存历史与 GUI 文本均有界，默认最多 5,000 行。
- 子进程输出直接落盘，不经过有界 OS pipe，因此输出速度不会因 GUI 收起或短暂
  忙碌而阻塞。
- 不在 GUI 主线程扫描整个日志文件；只处理 Core 返回的增量事件。

## 12. 测试与验收

### 12.1 Core 自动化测试

1. 同一命令延时写出 stdout、stderr 时，轮询可按 execution id 增量取得两者。
2. 命令输出超过常见 pipe 容量仍能退出，不发生死锁。
3. `MULTICMD` 和多个并发命令具有不同编号，事件不混淆。
4. START/CMD/EXIT 包含模块、质控员、`easyqcid` 和退出码。
5. 启动立即失败时，完整日志写入发生在暂存文件删除之前。
6. 非 UTF-8、ANSI 控制序列、超长行和不完整末行安全处理。
7. 文件日志失败会产生显式退化状态，查看器启动本身不被阻断。
8. 只删除超过 14 天且符合 EasyQC 命名规则的日志。
9. 源码模式与冻结模式使用同一输出合同；冻结环境清理回归测试继续通过。
10. Windows 文件句柄关闭顺序和 POSIX 进程组关闭测试继续通过。

### 12.2 Qt 自动化测试

1. 输出面板位于质控控制器底部，可调整高度并可展开/收起。
2. `QSettings` 恢复上一次可见状态和高度；启动命令不改变该状态。
3. 定时增量到达时正文更新；收起时仍能继续采集。
4. 超过 5,000 行后只保留最近 5,000 行，Core 日志仍完整。
5. 用户滚离底部时不自动抢回滚动位置。
6. “复制全部”“清空显示”“打开日志”行为符合定义。
7. stdout/stderr 不只靠颜色区分，accessible name 完整。
8. 中英文切换只翻译固定 UI，不翻译命令和外部输出。

### 12.3 集成与冻结包验收

1. 真实辅助命令逐步输出 stdout/stderr，冻结版底部面板实时可见。
2. 非零退出的完整输出保存在会话日志，界面仍显示简洁错误。
3. Linux 冻结应用通过 `--help`、Qt offscreen 和 xcb smoke。
4. 新 Debian 包通过完整性、解包和解包后启动验证。
5. HCP 环境用新版完整 onedir 产物测试 Freeview，若失败可从面板与会话日志取得
   实际退出输出。
6. Windows 与 macOS 在各自原生 runner 或实机验证文件句柄、系统日志打开和字体
   布局。

## 13. 完成标准

只有同时满足以下条件才视为完成：

- 外部查看器仍唯一经由 Core 启动；
- GUI 可实时观察并区分多命令 stdout/stderr；
- 收起状态记忆、5,000 行上限和 14 天完整日志均已验证；
- 大输出测试证明没有 pipe 反压死锁；
- 日志失败和命令失败都显式可诊断；
- 中英文、可访问性、冻结环境修复和现有质控工作流回归通过；
- 新 Linux 冻结产物与安装包由实现后的精确源提交重建；
- HCP 真实 Freeview 结果只在用户机器实际复测后报告，不以本机 smoke 冒充。
